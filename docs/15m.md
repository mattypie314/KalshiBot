# KalshiBot 15-minute BTC/ETH

**Standing one-liner:** Trade only BTC/ETH 15m on shard 2, settlement-index fair value, maker limits, one idea per asset per window (BTC+ETH both OK), $0.10–$1.50 risk, own $5 pot (separate from hourly) — quit at $0, ask at $10, flat is fine.

Operator: Crypto Clint. This bot is a sibling of hourly KalshiBot, not a replacement.

Not financial advice. A wrong contract can go to $0.

## What it trades

- **Only** `KXBTC15M` and `KXETH15M` (single-asset up/down).
- Crypto shard **exchange_index 2**.
- Out of scope: hourly (`KXBTCD` / `KXETHD`), other coins, sports, coin-race, metals.

Hourly `./kb scan` is unchanged and still ignores 15m fallback.

## Settlement (non-negotiable)

| Coin | CF Benchmarks id |
| --- | --- |
| BTC | **BRTI** |
| ETH | **ETHUSD_RTI** (never `ERTI`) |

Kalshi’s print is the **60-second average** before the window end. Missing or PROXY index → sit that coin. Coinbase is a display proxy only.

## Strategies

1. **Primary edge loop** — Python accepts minutes 3–5 of each `:00 / :15 / :30 / :45` ET window. Live Pi `kalshi-15m.timer` fires **once** per block at `:03 / :18 / :33 / :48` (not `:02`, not a `:02–:05` spray). One recheck if spot jumps ~half a sigma. Pass/Fail model-fair vs live mid + tape gate. Fail → skip. One idea per asset per window (BTC+ETH both OK when they independently Pass). Maker / post-only only; never cross; requote more passive if post-only would take.
2. **Optional last-minute maker** — last 3 minutes; favorites 74–93¢; size ~$0.10–$0.75. Does **not** stack with the edge loop in the same window by default (`STACK_LAST_MINUTE_WITH_EDGE=false`).

Hard skips:

- Under ~8 minutes left unless a last-minute look is decided
- Spread wider than edge vs mid
- News candle (2× typical vol or `NEWS_PAUSE=true`)
- Model within ~4¢ of live mid
- Revenge after a filled 15m loss
- Three filled 15m losses the same Eastern day
- **Chop veto** (`FIFTEEN_CHOP_VETO=true`, default on): after Pass, sit when recent 1m tape is chop (low ADX + tight Bollinger). Note looks like `PASS but chop veto`. Live and paper share this filter. Set `FIFTEEN_CHOP_VETO=false` to turn it off. Does not change maker/post-only, Turbo, or 99¢ cash-out.
- **Paper shadows live:** `fifteen_paper_log.jsonl` assumes a fill for the same window decision live used (same `collect_ideas` Pass/Sit). A later `scan` does not re-decide that window. Dry-only scans still paper Passes when live has not already ticked. Paper journal and pot stay separate from live.

## Pot / risk

- Dedicated 15m pot starts at **$5** (`artifacts/fifteen_pot.json`). Not `hourly_pot` / hourly `BANKROLL`.
- Pot → **$0**: quit and set **HALTED**.
- Pot → **$10**: notify / ask (do not auto-stop).
- Risk per idea **$0.10–$1.50** (preferred ~$0.75–$1.00).
- Bankroll for sizing = Kalshi `total_value` when the key can read it.
- Never size past remaining pot room or shard-2 cash.
- Ticket stop: ~25% of dollars risked **or** ~10% from fill (dollar stop capped ~$0.40). TP at fill+2¢ (`TAKE_PROFIT_CENTS=0.02`).
- **Hard cash-out at 99¢** (`CASH_OUT_BID=0.99`): held Yes if `yes_bid >= 0.99`; held No if `no_bid >= 0.99` / `yes_ask <= 0.01`. Beats early 95¢ cash-out and the +2¢ TP. Live oneshots flatten (label `cash_out_99`); they do not wait for an operator.
- **Early cash-out at 95¢ + time** (`EARLY_CASH_OUT_BID=0.95`, `EARLY_CASH_OUT_MINUTES=10`): flatten if the held-side bid is ≥ 95¢ **and** minutes to settlement are ≤ 10. After 99¢, ahead of +2¢ TP. Label `cash_out_95_time`.
- **Manual in-app flatten:** if a filled live ticket is gone via a Kalshi-app sell whose `order_id` is not our exit id, journal `manual_flatten`. Canceled unfilled rests are not immediately replaced — `fifteen_working` still sits **that coin** for the window; the other asset can still Pass.

## Live safety

- `HALTED=true` by default.
- Unattended live needs `LIVE_TRADING=true` **and** `CONFIRM_LIVE=YES` **and** `HALTED=false`.
- `--confirm LIVE` alone does **not** override `HALTED`.
- systemd timer units ship **disabled**. Do not enable until you mean to arm.

## Pi install (`/home/KalshiBot15`)

Sibling of hourly `/home/KalshiBot`. Separate checkout and **separate `.env`** so the two bots’ gates do not fight. Sharing a read of `~/.kalshi/` keys is OK. Never commit PEMs.

```bash
git clone https://github.com/mattypie314/KalshiBot.git /home/KalshiBot15
cd /home/KalshiBot15
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
chmod +x kb kb15
cp -n .env.fifteen.example .env
nano .env   # HALTED=true until you mean to trade
```

Ops:

```bash
./kb15                 # menu
./kb15 scan            # also: python -m src.fifteen scan   or   ./kb fifteen scan
./kb15 once            # dry-run limit payloads
./kb15 env
./kb15 env --prod
./kb15 eval            # bookkeeping dump (paper section + live journal)
./kb15 score           # Termius 15m PAPER board (not live)
./kb15 livescore       # Termius 15m LIVE board (fifteen_trade_log; not paper)
./kb15 paper           # same dump as eval
./kb fifteen live --prod   # type LIVE; HALTED still wins
kbscore-all            # combined LIVE board (15m + hourly pots); also: scoreall
```

Classic 15m Termius `livescore` stays on the Pi (`~/.local/bin`). Combined board is in-repo: `scripts/kbscore-all` → `python -m src.scoreboard_all`. Install without touching the 15m-only aliases:

```bash
cd /home/KalshiBot15   # or /home/KalshiBot — same script
git pull
chmod +x scripts/kbscore-all scripts/install-kbscore-all.sh
./scripts/install-kbscore-all.sh
# ln -sfn $PWD/scripts/kbscore-all ~/.local/bin/kbscore-all
# ln -sfn $PWD/scripts/kbscore-all ~/.local/bin/scoreall
```

`kbscore-all` / `scoreall` show 15M vs 1H plays, each pot, and a total. Live journals only — paper stays off this board.

Install units but **leave the timer disabled**. `git pull` does not update `/etc/systemd/system/` — recopy after every timer change so a future install cannot overwrite the live minute-3 unit:

```bash
sudo cp /home/KalshiBot15/scripts/kalshi-15m.service /home/KalshiBot15/scripts/kalshi-15m.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl disable --now kalshi-15m.timer
# do not touch kalshi-hourly.timer
# systemctl cat kalshi-15m.timer  →  OnCalendar=*-*-* *:03,18,33,48:00 America/New_York
```

Python still accepts minutes **3–5** if a oneshot is a bit late. The systemd unit is a **single** fire at minute 3 of each block (`:03/:18/:33/:48`). Do not reinstall a `:02` or `:02–:05` calendar.

When (and only when) you arm unattended live: set `HALTED=false`, `LIVE_TRADING=true`, `CONFIRM_LIVE=YES` in `/home/KalshiBot15/.env`, point `ExecStart` at `python -m src.fifteen live --prod --confirm LIVE`, then `enable --now`. Until then keep the timer disabled.

Logs: `journalctl -u kalshi-15m.service -n 80 --no-pager`

## Vol heuristic

The shared model is still zero-drift lognormal: `z = ln(K/S) / (hourly_vol * sqrt(hours_left))`. For a 15m window `hours_left` is ~0.25, so the same hourly-equivalent vol scales down automatically.

**TEMPORARY HEURISTIC:** 15m realized vol uses **90 minutes of 1-minute bars** (still expressed as hourly-equivalent vol). Hourly still uses ~4 hours. If 15m fairs look systematically off vs live mids, shorten or lengthen `FIFTEEN_VOL_LOOKBACK_MINUTES` before changing the model.
