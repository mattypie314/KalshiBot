# KalshiBot 15-minute BTC/ETH

**Standing one-liner:** Trade only BTC/ETH 15m on shard 2, settlement-index fair value, maker limits, one idea per window, $0.10–$1.50 risk, own $5 pot (separate from hourly) — quit at $0, ask at $10, flat is fine.

Operator: Crypto Clint. This bot is a sibling of hourly KalshiBot, not a replacement.

Not financial advice. A wrong contract can go to $0.

## What it trades

- **Only** `KXBTC15M` and `KXETH15M` (single-asset up/down).
- Crypto shard **exchange_index 2**.
- Out of scope: hourly (`KXBTCD` / `KXETHD`), other coins, sports, coin-race, metals.

Hourly `./kb scan` is unchanged and still ignores 15m fallback.

## Settlement (non-negotiable)

| Coin | CF Benchmarks id |
| --- | --- |
| BTC | **BRTI** |
| ETH | **ETHUSD_RTI** (never `ERTI`) |

Kalshi’s print is the **60-second average** before the window end. Missing or PROXY index → sit that coin. Coinbase is a display proxy only.

## Strategies

1. **Primary edge loop** — first 2–4 minutes of each `:00 / :15 / :30 / :45` ET window (timer fires at `:01 / :16 / :31 / :46`). One recheck if spot jumps ~half a sigma. Pass/Fail model-fair vs live mid. Fail → skip. One idea per window. Maker / post-only only; never cross; requote more passive if post-only would take.
2. **Optional last-minute maker** — last 3 minutes; favorites 74–93¢; size ~$0.10–$0.75. Does **not** stack with the edge loop in the same window by default (`STACK_LAST_MINUTE_WITH_EDGE=false`).

Hard skips:

- Under ~8 minutes left unless a last-minute look is decided
- Spread wider than edge vs mid
- News candle (2× typical vol or `NEWS_PAUSE=true`)
- Model within ~4¢ of live mid
- Revenge after a filled 15m loss
- Three filled 15m losses the same Eastern day

## Pot / risk

- Dedicated 15m pot starts at **$5** (`artifacts/fifteen_pot.json`). Not `hourly_pot` / hourly `BANKROLL`.
- Pot → **$0**: quit and set **HALTED**.
- Pot → **$10**: notify / ask (do not auto-stop).
- Risk per idea **$0.10–$1.50** (preferred ~$0.75–$1.00).
- Bankroll for sizing = Kalshi `total_value` when the key can read it.
- Never size past remaining pot room or shard-2 cash.
- Ticket stop: ~25% of dollars risked **or** ~10% from fill (dollar stop capped ~$0.40). TP at fill+2¢, or sell if bid is 99¢.

## Live safety

- `HALTED=true` by default.
- Unattended live needs `LIVE_TRADING=true` **and** `CONFIRM_LIVE=YES` **and** `HALTED=false`.
- `--confirm LIVE` alone does **not** override `HALTED`.
- systemd timer units ship **disabled**. Do not enable until you mean to arm.

## Pi install (`/home/KalshiBot15`)

Sibling of hourly `/home/KalshiBot`. Separate checkout and **separate `.env`** so the two bots’ gates do not fight. Sharing a read of `~/.kalshi/` keys is OK. Never commit PEMs.

```bash
git clone https://github.com/mattypie314/KalshiBot.git /home/KalshiBot15
cd /home/KalshiBot15
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
chmod +x kb kb15
cp -n .env.fifteen.example .env
nano .env   # HALTED=true until you mean to trade
```

Ops:

```bash
./kb15                 # menu
./kb15 scan            # also: python -m src.fifteen scan   or   ./kb fifteen scan
./kb15 once            # dry-run limit payloads
./kb15 env
./kb15 env --prod
./kb15 eval            # 15m paper + fifteen_trade_log
./kb15 paper
./kb fifteen live --prod   # type LIVE; HALTED still wins
```

Install units but **leave the timer disabled**:

```bash
sudo cp /home/KalshiBot15/scripts/kalshi-15m.service /home/KalshiBot15/scripts/kalshi-15m.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl disable --now kalshi-15m.timer
# do not touch kalshi-hourly.timer
```

When (and only when) you arm unattended live: set `HALTED=false`, `LIVE_TRADING=true`, `CONFIRM_LIVE=YES` in `/home/KalshiBot15/.env`, point `ExecStart` at `python -m src.fifteen live --prod --confirm LIVE`, then `enable --now`. Until then keep the timer disabled.

Logs: `journalctl -u kalshi-15m.service -n 80 --no-pager`

## Vol heuristic

The shared model is still zero-drift lognormal: `z = ln(K/S) / (hourly_vol * sqrt(hours_left))`. For a 15m window `hours_left` is ~0.25, so the same hourly-equivalent vol scales down automatically.

**TEMPORARY HEURISTIC:** 15m realized vol uses **90 minutes of 1-minute bars** (still expressed as hourly-equivalent vol). Hourly still uses ~4 hours. If 15m fairs look systematically off vs live mids, shorten or lengthen `FIFTEEN_VOL_LOOKBACK_MINUTES` before changing the model.
